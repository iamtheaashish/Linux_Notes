< Understanding Systemd >
Systemd is the default system and service manager for most modern Linux distributions.
Systemd system and service manager is used to start `stuff`. `Stuff` is called `Units`.

A `Unit` is a resource that systemd knows how to manage. There are different types of units:
$ systemd -t help
The most commonly used unit types are:
- service: A service unit, which defines a system service. Starts processes/daemons.
- socket: A socket unit, which defines a network or IPC socket.
- target: A target unit, which is a group of units that can be started or stopped together.
- mount: A mount unit, which defines a filesystem mount point.
- automount: An automount unit, which defines an automount point.
- timer: A timer unit, which defines a timer that can trigger other units.
- device: A device unit, which represents a device on the system.
- swap: A swap unit, which defines a swap space.
-------------------------------------------------------------------------------------------------
* Systemd Unit Location *
/run/systemd/system/      # Runtime units | Temporary units created at runtime | 1st priority
/etc/systemd/system/      # System-specific units | Generated by systemctl or manually created | 2nd priority
/usr/lib/systemd/system/  # Package-provided units | Never Edit Files Here | 3rd priority
-------------------------------------------------------------------------------------------------
```bash
[Unit]
Description=Vsftpd ftp daemon
After=network.target

[Service]
Type=forking
ExecStart=/usr/sbin/vsftpd /etc/vsftpd/vsftpd.conf

[Install]
WantedBy=multi-user.target
```
[Unit] Section (systemd):
Defines the unit and its dependencies.
After= starts this unit after the listed units.
Before= starts this unit before the listed units.
Used to control startup order between units.

[Service] Section (systemd):
Defines how the service starts, stops, and reports status.
ExecStart= command to start the service.
ExecStop= command to stop it.
Type= defines how the process starts (common types: forking, simple, oneshot).
Used for configuring the behavior of services.
-------------------------------------------------------------------------------------------------
* Understanding Systemd Mount Units *
Mount units are used to manage filesystem mount points.
Mount units have the suffix `.mount`.
`It is an alternative way to manage mounts instead of /etc/fstab file.`
-------------------------------------------------------------------------------------------------
* Understanding Systemd Socket Units *
Socket creates a method for applications to communicate with each other or with the system.
Socket units have the suffix `.socket`.
Every socket needs a corresponding service unit to handle the requests.
It may be a file or a port on which the systemd listens for incoming connections.
When a connection is made to the socket, systemd starts the corresponding service unit.
-------------------------------------------------------------------------------------------------
* Understanding Systemd Target Units *
Target units are used to group other units together.
Target units have the suffix `.target`.
Targets are used to bring the system to a specific state.
Common targets include:
- multi-user.target: A non-graphical multi-user system (similar to runlevel 3).
- graphical.target: A graphical multi-user system (similar to runlevel 5).
- default.target: The default target that the system boots into.
Targets help manage system states and dependencies.

< Managing Units through Systemd(systemctl) >
Just ensure `bash-completion` package is installed for auto-completion of systemctl commands.

+ systemctl status overview
1. loaded : Unit file is loaded into memory.
2. active(running) : Unit is currently running.
3. active(exited) : Unit has completed its task and exited.
4. active(waiting) : Unit is waiting for an event to occur.
5. inactive(dead) : Unit is not running.
6. enabled : Unit is configured to start at boot.
7. disabled : Unit is not configured to start at boot.
8. static : Unit cannot be enabled or disabled (usually because it is a dependency of another unit).

$ systemctl list-units -t service # List all active service units
$ systemctl list-units -t service --all # List all service units, including inactive ones
$ systemctl status -l httpd.service # Check the status of a specific service unit
-------------------------------------------------------------------------------------------------
* Managing Dependencies *
$ systemctl list-dependencies multi-user.target # List dependencies of a target unit
"You can use keywords like Reuqires, Requisites, Wants, Before, After in [Unit] 
section of unit files to manage dependencies."
-------------------------------------------------------------------------------------------------
* Managing Unit Options *
You might not remember the path of unit files.
$ systemctl show sshd.service # Show all properties of a unit
$ systemctl edit sshd.service # Edit the unit file in default text editor
$ systemctl cat sshd.service # Display the contents of the unit file
